# CrossApp

Наскрізний проєкт з крос-платформного програмування.

## Предметна область

**Бібліотека**

Основні сутності:

* `Book` — книга;
* `BookCopy` — примірник;
* `Reader` — читач;
* `Loan` — видача книги.

## Структура

```text
CrossApp/
│
├── data/
│   ├── sample.csv
│   └── library.json
│
├── src/
│   ├── Core/
│   │   ├── Abstractions/
│   │   ├── Domain/
│   │   ├── Dto/
│   │   ├── Events/
│   │   ├── Extensions/
│   │   ├── Import/
│   │   ├── Services/
│   │   ├── Storage/
│   │   └── SampleData.cs
│   │
│   └── Cli/
│       ├── Notifications/
│       ├── Program.cs
│       └── ReportConsole.cs
│
└── README.md

Призначення основних каталогів:

Core/Domain — доменні класи та бізнес-логіка.

Core/Dto — об'єкти передачі даних.

Core/Import — імпортери CSV та JSON.

Core/Services — сервісний шар, робота з бібліотекою та LINQ-звіти.

Core/Storage — інтерфейси та реалізації сховищ.

Core/Events — класи подій.

Core/Extensions — методи розширення.

Core/Abstractions — абстракції та контракти.

Cli — консольний інтерфейс, меню та запуск команд.

data — файли з даними.

`Cli` використовує бібліотеку `Core` через `ProjectReference`.

## Публікація

### Self-contained

```bash
dotnet publish src/Cli -c Release -r win-x64 --self-contained true
```

```bash
dotnet publish src/Cli -c Release -r linux-x64 --self-contained true
```

### Framework-dependent

```bash
dotnet publish src/Cli -c Release -r win-x64 --self-contained false
```

Self-contained містить .NET Runtime, а framework-dependent потребує встановленого Runtime.

## Лабораторна робота 4

Предметна область: Бібліотека.

Основні сутності:
- BookCopy — примірник книги;
- Loan — видача книги.

Інваріанти:
- інвентарний номер не може бути порожнім;
- назва книги не може бути порожньою;

Для створення сутності використовується фабричний метод Create().
Для перетворення між доменною сутністю та DTO використовуються
методи ToDto() та FromDto().

## Лабораторна робота 5 — Сервісний шар і сховища

У роботі реалізовано абстракцію сховища бібліотечних примірників через інтерфейс `IBookStore`.

Створено дві реалізації:
- `InMemoryBookStore` — зберігає примірники в оперативній пам’яті.
- `FileBookStore` — зберігає примірники у JSON-файлі.

Клас `LendingService` реалізує операції перегляду, пошуку, додавання, видачі, повернення та видалення примірників. Він залежить від інтерфейсу `IBookStore`, а не від конкретного сховища.

Вибір сховища виконується вручну в `Program.cs`:
- `dotnet run --project src/Cli` — сховище в оперативній пам’яті.
- `dotnet run --project src/Cli -- --file` — файлове сховище `data/library.json`.

Ручне впровадження залежностей реалізовано через створення вибраного сховища в точці входу та передавання його в конструктор `LendingService`. DI-контейнер не використовується.

 ## Додаткові завдання

1. Декоратор CachingBookStore

Реалізовано декоратор для кешування результатів пошуку примірників за ID. Це зменшує кількість повторних звернень до сховища.

2. Пошук Search

У класі LendingService додано метод Search, який приймає умову Func<BookCopy, bool> і дозволяє шукати примірники за різними критеріями.

3. Фабрика StoreFactory

Створено фабрику для автоматичного вибору сховища залежно від аргументів запуску програми: FileBookStore для --file або InMemoryBookStore за замовчуванням.

## Лабораторна робота 6 — Події, сповіщення та делегати

У роботі реалізовано механізм подій для відстеження змін бібліотечних примірників.

Створено:
- `BookCopyChangeKind` — перелік типів змін: додавання, видача, повернення та видалення примірника.
- `BookCopyChangedEventArgs` — клас, який зберігає інформацію про подію: ID примірника, тип зміни та час її виникнення.
- Подію `Changed` у класі `LendingService`, яка спрацьовує після виконання операцій із примірниками.

Під час зміни даних сервіс генерує подію, на яку можуть підписуватися інші частини програми та виконувати відповідну обробку.

## Додаткові завдання

1. Інтерфейс сповіщень `INotificationSink`

Створено інтерфейс `INotificationSink` із методом `Notify(string message)`.

Реалізовано дві реалізації:
- `ConsoleSink` — виводить повідомлення в консоль.
- `FileSink` — записує повідомлення у файл.

Реалізації передаються до `LendingService` через конструктор. Це приклад ручного впровадження залежностей (Manual Dependency Injection).

2. Делегат `Action<string>` для імпорту

У `BookCsvImporter` додано параметр `Action<string>? reportSkipped`, який дозволяє передавати функцію для повідомлення про пропущені рядки під час імпорту CSV.

Якщо рядок містить помилку, формується повідомлення з номером рядка та причиною пропуску. Передана функція виводить це повідомлення в консоль.

3. Асинхронні обробники подій

Розглянуто використання `async void` для асинхронних обробників подій.

Оскільки стандартний делегат `EventHandler` повертає `void`, асинхронний обробник події може використовувати `async void`.

Основні недоліки такого підходу:
- неможливо очікувати завершення обробника через `await`;
- складніше перехоплювати винятки;
- помилки можуть стати необробленими.

Для звичайних асинхронних методів рекомендується використовувати `async Task`.



## Лабораторна робота 7 — LINQ

У роботі реалізовано обробку та аналіз даних бібліотечних примірників за допомогою LINQ.

Створено:
- `BookCopyReportService` — сервіс для формування звітів про книги.
- `EnumerableExtensions` — клас із власним LINQ-методом `TopBy`.
- `ReportConsole` — клас для запуску звітів через консольні команди.
- `LinqBenchmarkService` — сервіс для порівняння продуктивності LINQ-запитів.

Реалізовано фільтрацію, сортування, групування, підрахунок, пошук та об'єднання даних.

## Додаткові завдання

**1. Фільтрація та сортування**

Реалізовано отримання доступних і виданих книг, а також сортування книг за довжиною назви та інвентарного номера.

**2. Групування та підрахунок**

Реалізовано групування книг за доступністю та підрахунок загальної кількості книг, доступних і виданих примірників.

**3. Пошук книг**

Додано пошук книг за частиною назви за допомогою LINQ.

**4. Query Syntax та Method Syntax**

Реалізовано два способи групування книг:
- `Query Syntax` — запис LINQ-запитів у вигляді SQL-подібного синтаксису.
- `Method Syntax` — використання методів `GroupBy`, `Select`, `Where` та інших.

**5. Відкладене виконання LINQ**

Продемонстровано відкладене виконання запитів і різницю між запитом та його матеріалізацією за допомогою `ToList()`.

**6. Об'єднання даних JOIN**

Реалізовано об'єднання інформації про бібліотечні примірники та історію операцій за допомогою `join` за ідентифікатором книги.

**7. Власний метод TopBy**

Створено метод розширення `TopBy`, який сортує елементи за заданим критерієм і повертає вказану кількість перших результатів.

**8. Порівняння продуктивності**

За допомогою `Stopwatch` реалізовано вимірювання часу виконання LINQ-запитів із проміжним `ToList()` та без нього.

# Лабораторна робота №8 — Асинхронне програмування

У роботі реалізовано асинхронну обробку даних бібліотечних примірників за допомогою `async/await`, механізмів скасування операцій та обробки винятків.

Створено та вдосконалено:
- `JsonBookCopyImporter` — клас для асинхронного імпорту бібліотечних примірників із JSON-файлів.
- `LendingService` — сервіс для виконання операцій із бібліотечними примірниками та асинхронного імпорту даних.
- `IBookCopyImporter` — інтерфейс для реалізації механізму імпорту книг.

Реалізовано асинхронне завантаження даних, перевірку коректності інформації, обробку помилок, скасування операцій та відстеження прогресу імпорту.

## Додаткові завдання

### 1. Асинхронний імпорт даних

Реалізовано завантаження бібліотечних примірників із JSON-файлу за допомогою `async/await`. Це дозволяє виконувати операції введення-виведення асинхронно, не блокуючи потік виконання.

### 2. Обробка помилок

Додано обробку некоректних даних під час імпорту. Для перетворення помилок створення об'єктів на доменні винятки використовується механізм `try/catch`.

### 3. Скасування операцій

Реалізовано підтримку `CancellationToken`, який дозволяє перервати асинхронну операцію на вимогу користувача. Також додано перевірку скасування під час обробки бібліотечних примірників.

### 4. Обмеження часу виконання

Реалізовано механізм обмеження часу імпорту за допомогою `CancellationTokenSource`. Використовується `CreateLinkedTokenSource` для об'єднання токена користувача та токена тайм-ауту. Якщо час виконання перевищено, генерується `TimeoutException`.

### 5. Відстеження прогресу

Додано підтримку `IProgress<int>` для відображення відсотка виконання імпорту. Після обробки кожного примірника оновлюється значення прогресу.

### 6. Асинхронне перерахування

Розглянуто використання `IAsyncEnumerable` та `await foreach` для послідовної обробки даних. Атрибут `EnumeratorCancellation` використовується для передавання токена скасування асинхронному перерахуванню.

### 7. Тестування асинхронних операцій

Передбачено перевірку роботи асинхронного імпорту, обробки помилок і скасування операцій за допомогою модульних тестів.

### 8. Перевірка покриття коду тестами

Передбачено можливість аналізу покриття коду тестами за допомогою команди `dotnet test --collect:"XPlat Code Coverage"`. Це дозволяє оцінити, які частини програми перевіряються автоматизованими тестами.
